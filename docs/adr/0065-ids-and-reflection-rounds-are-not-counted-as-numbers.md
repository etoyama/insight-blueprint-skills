# ADR-0065: ツリーの検査は、id と振り返りの回を数として数えない

## Status

Accepted（[ADR-0025](0025-cited-answers-checked-after-writing.md) と [ADR-0058](0058-a-tree-decision-may-cite-the-events-behind-its-reason.md) の「文の数が引用先の本文にある」に、数えないものを足す）

## Context

Epic 35（[#284](https://github.com/etoyama/insight-blueprint-skills/issues/284)、[DesignDoc](../design/epic-35-hand-over-questions.md)）の初版で決めた。
ツリーの検査は、現時点の答えの文と、引用を持つ論点ツリーの決定の理由に出てくる数が、引用した出来事の本文にあるかを確かめる。無ければ書かせない。
[#277](https://github.com/etoyama/insight-blueprint-skills/issues/277) は、理由に論点の id や「2回目の振り返り」と書くと拒まれることを挙げた。

比較の土台にした事実。

- 合成シナリオで、理由に `LIB-Q06` と書くと `number-not-cited: 06` で拒まれた。実データのテーマでも、最初の決定で同じ形で拒まれた。
- 実データで、答えの文の「率比が1を超える」の 1 が拒まれた。その値を書いた別の出来事を根拠に足して通した。
- 検査は `skills/_shared/tree_check.py` の `numbers_in` が文から数を拾い、`_cite_problems` が引用先の本文の数と比べる。
- 3つの案を、通したい文4つと拒みたい文6つに当てた（架空の例、各1回）。結果は下の表にある。
- 確かめていないこと: 比べる相手の値で、書き手が実際にどのくらいつまずくか。

| 文 | 今 | 案A | 案B | 案C |
|---|---|---|---|---|
| 通したい: LIB-Q06 と LIB-Q05 は互いを待たない | 拒む | 通る | 通る | 通る |
| 通したい: 2回目の振り返りで | 拒む | 通る | 通る | 通る |
| 通したい: 率比が1を超えるので | 拒む | 拒む | 通る | 通る |
| 通したい: 率比は1.34で、支持の線の1.2以上だった | 拒む | 拒む | 通る | 通る |
| 拒みたい: 期限切れは200件を超える | 拒む | 拒む | 拒む | 通る |
| 拒みたい: LIB-Q06 では期限切れが30%増えた | 拒む | 拒む | 拒む | 拒む |
| 拒みたい: 2回目の通知で来館した人は40人だった | 拒む | 拒む | 拒む | 拒む |
| 拒みたい: LIB-Q99 の結果から（無い論点） | 拒む | 拒む | 拒む | 拒む |
| 拒みたい: 5回目の振り返りで決めた（まだ無い回） | 拒む | 拒む | 拒む | 拒む |
| 拒みたい: 率比は2以上だった | 拒む | 拒む | 拒む | 通る |

「率比は1.2だった」（判定の基準の値を、結果として書く）は、案B だけが通す。

## Problem

- 課題1: 理由に論点の id を書くと、id の数字が拒まれる。まとめて任せると、理由に複数の id を書きたくなる。
- 課題2: 「N回目の振り返り」の N も拒まれる。
- 課題3: 比べる相手の値（「1を超える」の 1）も拒まれる。

扱わない範囲: 引用を持たない決定の理由に書いた数の検査（ADR-0058 が塞がないと決めた）。

## Decision Analysis

| # | 基準 | 区分 | 分類 | 重み（決めた人） | 出典 |
|---|---|---|---|---|---|
| M1 | 記録に無い数を結果として書いた文を拒む | Must | - | - | [docs/PRD.md](../PRD.md) の非機能要件、ADR-0025 |
| W1 | id と振り返りの回を書いた理由が通る | Want | 解決 | 高（人間。#277 を Epic に入れた） | 課題1、課題2 |
| W2 | 比べる相手の値を書いた文が、書き直さずに通る | Want | 解決 | 中（Claude の推測） | 課題3 |

- 案A: 数えないのは、論点ツリーにある id と、「N回目の振り返り」だけにする。
- 案B: 案A に加えて、引用した出来事の分析設計が持つ、問い・検証仮説・判定の基準にある数も、記録にある数として扱う。
- 案C: 案A に加えて、「を超える」「以上」「以下」などの前の数を数えない。
- 何もしない。

| 案 | 起きうる悪い結果 | 抑え方 |

| 案A | 比べる相手の値で、書き手が1回つまずく | 拒んだときに直し方を言う |
| 案B | 判定の基準の値が、結果として分析者に届く | 抑えにくい。文の中の数が基準か結果かは、コードには分からない |

## Decision

案A を採る（人間の判断、2026-11-27）。決め手は W3 である。

1. ツリーの検査は、文の数を引用先と比べる前に、次の2つを数として数えない。
   - 論点ツリーにある論点の id と、論点に結んだ分析設計の id と、その分析設計の出来事の id。
   - 「N回目の振り返り」の N。N が今の振り返りの回以下のときに限る。
2. 論点ツリーに無い論点や分析設計の id の数字と、今の回より大きい N は、今までどおり数として数える。
3. それ以外の数は、今までどおり、引用した出来事の本文に無ければ拒む。比べる相手の値も拒む。
4. 数を拒んだとき、`tree_io` は直し方を言う。その値を書いた出来事を根拠に足すか、文から数を外す。
5. 現時点の答えの文と、引用を持つ論点ツリーの決定の理由に、同じ規則を使う。

## Consequences

### Positive

- 理由と答えの文に、論点・分析設計・出来事の id と、振り返りの回を書ける。
- 守りは緩まない。id は論点ツリーにあることを、回は今の回以下であることを確かめる。

### Negative

- 比べる相手の値のつまずきは残る。実データで使う段で頻度を見て、多ければ案B を考え直す。
- 「N回目の振り返り」と違う言い方（「振り返りの2回目」など）の数は、今までどおり拒む。
- 引用を持たない決定の理由に書いた数は、今までどおり検査されない。

## Alternatives considered

- **小さい整数（0、1、2）を数えない** — 「2件だった」のような、記録に無い結果が通る。
