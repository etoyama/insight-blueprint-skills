# ADR-0027: 既定の許可リストは常に許し、パッケージ許可リストのファイルはそこにパッケージを足す

## Status

Accepted

## Context

notebook の契約（`skills/analysis-notebook/references/notebook-contract.md`）は、8つの cell の形を決めている。
cell 0 の返り値は `(pd, plt, np, LineageSession, tracked_pipe, export_lineage_as_mermaid, json, Path)` に固定され、cell 2 は `import marimo as mo` を行う。
つまり契約に従う notebook は、`pandas`・`matplotlib`・`numpy`・`insight_blueprint`・`marimo` を必ず import する。
この5つは、既定の許可リスト（plugin の env に最初から入っているパッケージ）とちょうど一致する。

同じ契約は、notebook のトップレベルの `import X` について、`X` がパッケージ許可リストにあることを求める。
[ADR-0021](0021-default-package-allowlist.md) は、`.insight/rules/package_allowlist.yaml` があるときはその中身だけを許可リストにし、既定の許可リストは足さないと決めた。
そのため、ファイルに5つのどれかを書かないと、契約が求める import が許可リストの外になる。
ADR-0021 はこの食い違いを Negative に書いたが、塞がなかった（issue #108）。

2026-11-21 に人間が、まず `marimo` と `insight_blueprint` の2つを常に許す案を選んだ。
その実装のレビューで、契約が `pandas`・`matplotlib`・`numpy` も必ず import させていることが分かり、前提を直して人間に聞き直した。
人間は5つ全部を常に許す案を選び、新しい ADR を書いて単発の PR で出すと決めた。
その案では標準ライブラリを丸ごと許可リストの対象から外していたが、2回目のレビューで `socket` や `subprocess` まで照合を素通りすることが分かった。そこで、外すのは契約が自分で import する `json` と `pathlib` だけに絞った。人間が選んだ案より狭める変更なので、PR の説明に書いて人間に確かめる。

比較の前提にした事実は次のとおり。

- パッケージ許可リストを読むコードはリポジトリに無い。照合は driver（LLM）が SKILL.md と契約の文に従って行う（ADR-0021。`grep -rln package_allowlist skills src` で確かめた）。
- `/analysis-auto` は、許可リストの外の import がある notebook を自動で実行せず、KEEP ゲートで止める（`skills/analysis-auto/SKILL.md` の Workflow）。
- ADR-0021 が「ファイルがあるときは既定を足さない」とした理由は、分析者がファイルで許可を絞れるようにするためだった（ADR-0021 の Alternatives considered）。
- 契約は標準ライブラリの `json` と `pathlib` も import するが、どの許可リストにも無い。契約の文を文字どおり読むと、これも許可リストの外になる。
- リポジトリの見本（`.insight/rules/package_allowlist.yaml`）には `marimo` と `insight_blueprint` が無かった。見本を写したプロジェクトは毎回止まる。
- 実際に `/analysis-auto` を走らせて止まるかは確かめていない。上の文を読んで導いた。

## Problem

- 課題1: パッケージ許可リストのファイルを置いた分析者は、契約が import する5つを1つでも書き忘れると、notebook の手前の KEEP ゲートで毎回止まる。分析者が自分で選んだパッケージではないので、直し方も分かりにくい。
- 課題2: 契約の文を文字どおり読むと、契約が自分で import する標準ライブラリ（`json`、`pathlib`）も許可リストの外になる。
- 課題3: リポジトリの見本自体が契約を破っており、写した人は必ずこの穴に落ちる。

扱わない範囲: cell 0 の import を methodology ごとに変えられるように、契約の cell の形を変えること。

## Decision Analysis

| # | 基準 | 区分 | 分類 | 重み（決めた人） | 出典 |
|---|---|---|---|---|---|
| M1 | 契約どおりの notebook が、ファイルの中身のせいで KEEP ゲートに止まらない | Must | - | - | 課題1、課題3 |
| M2 | 契約の外のパッケージは、引き続きファイルで許可を絞れる | Must | - | - | ADR-0005 |
| W1 | ADR-0021 の決定をどこまで変えるか（少ないほどよい） | Want | 費用 | 中（Claude の推測） | ADR-0021 |
| W2 | 契約と許可リストがずれたときに、テストで気づける | Want | 費用 | 高（Claude の推測） | レビューの指摘 |

案は次の3つ。

- 案 A: `marimo` と `insight_blueprint` の2つだけを、ファイルにかかわらず常に許す。
- 案 A': 既定の許可リスト（契約が import する5つ）を常に許し、ファイルはそこにパッケージを足す。cell 0 が import する標準ライブラリ（`json`、`pathlib`）は許可リストに書かなくてよい。
- 案 B: 振る舞いは変えない。見本を直し、ファイルには既定の許可リストを必ず写すよう案内する。

| Must | 案 A | 案 A' | 案 B | 何もしない |
|---|---|---|---|---|
| M1 | 満たさない（`pandas` などを書き忘れると止まる） | 満たす | 満たさない（案内を読まなかった人は止まる） | 満たさない |
| M2 | 満たす | 満たす（5つは契約が必ず使うので、絞っても守れるものが無い） | 満たす | 満たす |

Must を通るのは案 A' だけなので、Want で比べる相手は残らない。案 A' の Want の評価は次のとおり。

| Want | 案 A' |
|---|---|
| W1 | ADR-0021 の「ファイルがあるときは既定を足さない」を覆す。ファイルが無いときの扱いと、`null` を読めないファイルだけに使う決まりは変えない。 |
| W2 | 構造テストが、契約の cell が使う名前（cell 0 の返り値と cell 2 の `mo`）の import 元から標準ライブラリを除いたものと、既定の許可リストの import 名とが一致することを確かめる。cell 0 に名前を足すと、どちらの向きのずれでも落ちる。 |

- 差がつく基準: M1。
- 感度: M1 を Want に下げ、ADR-0021 を覆さないことを重く見るなら、案 A か案 B に変わる。

| 案 | 起きうる悪い結果 | 抑え方 |
|---|---|---|
| 案 A | `pandas` などを書き忘れたファイルで、同じように止まり続ける。 | 無い。 |
| 案 A' | 既定の許可リストに、契約が使わないパッケージを足すと、絞れないパッケージが増える。 | 既定の許可リストと契約の cell が import する名前の一致を、構造テストで縛る。 |
| 案 B | 案内で済ませるので、同じ穴が残る。 | 見本を直し、写す人だけは救う。 |
| 何もしない | 見本を写した人が全員止まる。 | 無い。 |

## Decision

案 A' を採る。決め手は M1 である。契約が必ず書かせる import をパッケージ許可リストで拒めても、守れる境界は無く、分析者が落ちる穴だけが残る。

- 既定の許可リストは、ファイルがあるかどうか、何が書いてあるかにかかわらず許す。ファイルは既定の許可リストにパッケージを足す。
- 既定の許可リストは、契約の cell が import するパッケージで、plugin の env に最初から入っているパッケージでもある。正本は notebook の契約の「Default allowlist」節に置く。
- cell 0 が import する標準ライブラリ（`json`、`pathlib`）は、許可リストに書かなくてよい。ほかの標準ライブラリは、これまでどおりパッケージと同じように照らす。`socket` や `subprocess` のように宣言した source の外へ届くモジュールを、照合から外さないためである。
- premortem の `allowlist_ok` と `/analysis-auto` が notebook を自動で実行してよいかの判定は、既定の許可リストにファイルを足したものを使う。
- ファイルが読めないときだけ `null` にする、という ADR-0021 の決定は変えない。空の `allowed_packages` は何も足さない。
- リポジトリの見本は、既定の許可リストより先のパッケージだけを書く形にする。
- 振る舞いを変えるが、変更は文書と構造テストだけで、効果は ADR-0021 の1つの決定に閉じる。ADR-0012 の例外として、Epic にせず単発の PR で出す（人間が決めた）。

## Consequences

### Positive

- ファイルを置いても、契約の import のせいで `/analysis-auto` が notebook の手前で止まることは無くなる。既にあるファイルも直さなくてよい。
- 1つパッケージを足したいときは、そのパッケージだけをファイルに書けばよい。
- 既定の許可リストが契約の cell や plugin の env とずれると、構造テストが落ちる。

### Negative

- 分析者は、ファイルで `pandas` などの既定のパッケージを禁じられなくなる。契約がそれらを必ず使う限り、禁じても notebook は動かない。
- 照合は今も driver の解釈で行う。SKILL.md の文が守られるかは、構造テストでは確かめられない。
- cell の名前と import 元の対応（`pd` は `pandas` など）は、テストの側に書いている。cell 0 に名前を足すとテストが落ちるので、そのときにこの対応も直す。
- `statistics` のような標準ライブラリを使う分析は、今までどおりファイルに書く必要がある。
- ADR-0012 の例外を1つ作った。

## Alternatives considered

- **契約の cell 0 の import を、methodology ごとに変えてよいことにする案** — 契約の cell の形を変えることになり、この issue の範囲を超える。#108 の穴は、許可リストの扱いを変えるだけで塞げる。
