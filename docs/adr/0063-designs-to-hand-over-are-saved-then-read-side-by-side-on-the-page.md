# ADR-0063: 任せる分析設計は先に保存し、ページで横に並べて読む

## Status

Accepted（[ADR-0007](0007-upstream-judgment-gates.md) の「4つの確認は `design_io create` の前に走らせる」を、まとめて任せる流れについて置き換える）

## Context

Epic 35（[#284](https://github.com/etoyama/insight-blueprint-skills/issues/284)、[DesignDoc](../design/epic-35-hand-over-questions.md)）の初版で決めた。
ADR-0007 は、分析設計の確認を4つに分け、保存の前（したがって premortem の前）に1つずつ聞くと決めた。
互いを待たない論点をまとめて任せるとき、分析者は任せる前に1回、任せる分析設計を横に並べて読む（任せる前の確認）。読む中身は4つの確認と同じである。

比較の土台にした事実。

- 実データで手で通したとき、分析設計3つぶんの確認は、対話エージェントがチャットに書いた表で1回で読めた（1回）。今の skill のままなら12回止まる。
- チャットの表のセルにはコードブロックを置けない。分析設計2つぶんで SQL が短くても、表は読みにくい幅になった（試した）。
- 論点ツリーの HTML は手元のファイルで、分析者は今も決める前にそのパスを開く（`skills/analysis-auto/SKILL.md` の Step 3 の 8）。
- Artifact に置くことは外へ送ることで、送る前に承認で止まる（[ADR-0016](0016-approval-before-external-send.md)）。
- 今の確認は「探索の問い」と「検証仮説」を別の形で聞く。並べると、行の名前が揃わない。
- 論点ツリーの HTML は script を持たない。[ADR-0024](0024-question-tree-yaml-and-generated-html.md) は、外部の script と stylesheet を読まないと決めている。
- 人間がデスクトップアプリのペインで試作を試した。コメント欄に書けて、ボタンでページに出た文は手でコピーできた。クリップボードには入らなかった（1回）。
- 確かめていないこと: 分析設計3つぶんを、コードが作ったページで分析者が1回で読み切れるか。

## Problem

- 課題1: 分析設計ごとに4回止まる。3つ任せると12回になる。
- 課題2: 並べて読むとき、分析設計の間で粒度や分母が違うことが判断の要になる。目で探すと見落とす。
- 課題3: 「このまま任せる／直してから任せる」の二択では、分析設計ごとの直しを1回で返せない。聞かれる回数が減っても、手戻りが増える。

扱わない範囲: 戻ったときに図を並べる場所（次の Epic）。同じ回答者の同じ回答を使う分析の表示（[#236](https://github.com/etoyama/insight-blueprint-skills/issues/236)）。

## Decision Analysis

| # | 基準 | 区分 | 分類 | 重み（決めた人） | 出典 |
|---|---|---|---|---|---|
| M1 | SQL・抽出条件・分母・粒度・主指標を、実行の前に読んで直せる | Must | - | - | ADR-0007 |
| M2 | 見せるために止まる回数が増えない | Must | - | - | 課題1 |
| W1 | 違う行の印が、同じ規則で付く | Want | 解決 | 高（人間が案B を選んだ） | 課題2 |
| W2 | SQL を全文、崩れずに読める | Want | 解決 | 高（人間。ADR-0007 の経緯） | M1 の程度 |
| W3 | 作る・保守するものが少ない | Want | 費用 | 中（Claude の推測） | YAGNI |

- 案A: チャットの表。対話エージェントが表を書く。
- 案B: 手元の HTML。分析設計を先に保存し、コードが論点ツリーの HTML の中に節を作る。チャットにはパスと、違う行の要約を出す。
- 案C: Artifact。案B の HTML を Artifact に置く。
- 何もしない（分析設計ごとに4回）。

| Must | 案A | 案B | 案C | 何もしない |
|---|---|---|---|---|
| M1 | 満たす | 満たす。直しは `in_review` の分析設計を更新する | 満たす | 満たす |
| M2 | 満たす | 満たす | 満たさない。送る前の承認で1回止まる | 満たさない |

| Want | 案A | 案B |
|---|---|---|
| W1 | 印は対話エージェントが付ける。付け忘れと付け過ぎが起きうる | 印はコードが付ける。同じ行の値が違えば付く |
| W2 | 表のセルに入れると崩れる | 分析設計ごとに畳んで、全文を出せる |
| W3 | コードは増えない | 表示のコードと、確認の前に保存する流れへの変更 |

- 差がつく基準: W1・W2 と W3 が逆向きである。
- 感度: W3 を高にすると案A。案A は、確認したものと保存したものが別物になりうる。

| 案 | 起きうる悪い結果 | 抑え方 |
|---|---|---|
| 案A | 印が抜け、粒度の違いに気づかずに任せる | skill の文に頼る |
| 案B | 確認の前に分析設計を保存するので、ADR-0007 と順番が変わる | 確認は premortem とデータに触る前に置いたままにする |
| 案B | 分析者が HTML を開かずに「任せる」と答える | チャットにも、違う行の要約を必ず出す |
| 案C | 止まる回数が増える。置いた後に直すと、古い内容が残る | 抑えにくい |
| 何もしない | 課題1〜3 が残る | 無い |

## Decision

案B を採り、コメント欄を足す（人間の判断、2026-11-27）。決め手は W1 と W2 である。コメント欄は人間の案である。

1. まとめて任せる流れでは、対話エージェントは任せる分析設計を `in_review` で保存し、論点に結んでから、任せる前の確認を求める。確認の前には、premortem も回さず、データにも触らない。
2. 論点ツリーの HTML は、最新の決定が指す論点に結んだ実行前の分析設計を、列に並べた節を持つ。行は、意図、何に答えるか、判定の基準、対象、粒度、分母、データソース、手法、主指標、抽出、図である。
3. 「何に答えるか」の行は、探索では問いを、検証では検証仮説を出す。判定の基準の行は、探索では基準が無いことを文で出す。
4. 対象・粒度・分母・データソースの行は、値が分析設計の間で違えば、コードが印を付ける。対象・粒度・分母は分析設計の項目から読む（[ADR-0066](0066-a-design-may-state-its-population-grain-and-denominator.md)）。
5. 対話エージェントは、ページのパスと、印の付いた行の要約をチャットに出して、確認を求める。
6. 節は分析設計ごとのコメント欄と、コメントをまとめるボタンを持つ。ボタンは、書かれたコメントを、分析設計の id を添えた1つの文にして、ページに出す。クリップボードに入れることも試みるが、入らなくてもページの文は読める。
7. 論点ツリーの HTML は、この節のために script を持つ。script はページの中の文を集めて出すだけで、外へ何も送らず、外部の script も読まない。
8. 分析者が貼ったコメントを、対話エージェントは分析設計ごとに review コメントとして記録し、分析設計を直し、節を作り直して、もう一度確認を求める。任せないと決めた分析設計は、理由つきで止める（[ADR-0064](0064-a-handed-over-analysis-asks-before-changing-what-was-read-and-can-be-stopped.md)）。
9. 単独で起動した `/analysis-design` と、論点を1つだけ調べる巡回の4つの確認は、ADR-0007 のまま変えない。

## Consequences

### Positive

- 分析者が確認したものと、実行されるものが、同じ記録になる。
- 違う行の印は、書き手によらず同じ規則で付く。
- 分析設計ごとのコメントを1回で返せる。コメントは review コメントとして残り、分析ノートで読める。

### Negative

- 確認の前に分析設計が保存される。確認の途中でやめると、`in_review` の分析設計が論点に結ばれたまま残る。その分析設計は、実行前として論点ツリーに出る。
- 論点ツリーの HTML が初めて script を持つ。Artifact に置いたときに同じ script が動くかは確かめていない。
- 印は値の文字が違えば付く。同じ意味を違う言葉で書いた行にも付く。
- 論点を1つだけ調べる巡回は4回止まるままである。1つのときにも同じ節を使うかは、この決定では決めない。

## Alternatives considered

- **分析設計を保存せず、対話エージェントが下書きを渡してコードに並べさせる** — 確認したものと、後から保存するものが別物になりうる。下書きの置き場も新しく要る。
- **デスクトップアプリの機能で、手元の HTML にコメントを付ける** — そういう機能があるかを確かめられなかった。アプリに頼ると、ほかの環境で使えない。
