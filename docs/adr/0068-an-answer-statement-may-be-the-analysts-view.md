# ADR-0068: 現時点の答えの文は、分析者の見立てとして書ける

## Status

Accepted

## Context

Epic 36（[#302](https://github.com/etoyama/insight-blueprint-skills/issues/302)、[DesignDoc](../design/epic-36-before-the-analyst-answers.md)）の初版で決めた。
[ADR-0025](0025-cited-answers-checked-after-writing.md) は現時点の答えの文をすべてエージェントに書かせ、書いた後に検査すると決めた。
「答えは人が書く」案は、新人の分析者に統合を任せると委ねる価値が落ちる、という理由で落とした。
Epic 35 の実データで使う段で、分析者は逆の不満を言った。分析設計をまたいだ自分の見立てを主題に結び付けたいのに、
求められるのは根拠の id を選ぶことだった（[#298](https://github.com/etoyama/insight-blueprint-skills/issues/298)）。

比較の土台にした事実（v0.22.0 を読み、実データのテーマの記録を読むだけにして数えた。値は書かない）。

- 答えの文（`AnswerStatement`）は種類・本文・引用の3つを持つ。複数の分析設計の出来事を引用できる。
  実データの主題の答え13文のうち6文は、2つの分析設計の出来事を引用していた。
- 分析者の言葉が残るのは、分析設計ごとの `conclude` と、論点ツリーの決定の理由だけである。テーマには journal が無い。
- `/analysis-reflection` の Step T2 は、新しい結果が関わらない文でも、「引用した出来事より多くを言う claim」を直させる。
- 論点ツリーの決定の理由は、分析者の言葉で書き、根拠はエージェントが探して読み上げ、検査の違反は分析者に聞く
  （[ADR-0058](0058-a-tree-decision-may-cite-the-events-behind-its-reason.md)）。
- `TreeDecision` に既定値つきの項目を足しても、保存済みの論点ツリーはそのまま読めた（Epic 35 の初版で確かめた）。

## Problem

- 課題1: 分析者が分析設計をまたいだ見立てを書く場所が無い。主題の答えは、エージェントの下書きを待つしかない。
- 課題2: 引用を越える見立てを claim に書いても、次の回のエージェントが決まりに従って直す。分析者の言葉が知らないうちに変わる。
- 課題3: 引き継いだ読み手は、分析者の見立てと、エージェントがまとめた文を見分けられない。

扱わない範囲: 途中の論点への見立てを聞くこと。数を含まない言い過ぎを機械で止めること。

## Decision Analysis

| # | 基準 | 区分 | 分類 | 重み（決めた人） | 出典 |
|---|---|---|---|---|---|
| M1 | 保存済みの論点ツリーの YAML がそのまま読める | Must | - | - | 不変条件（正本は YAML） |
| M2 | 文に出てくる数は、引用した出来事の本文にあるものだけ | Must | - | - | ADR-0025 |
| W1 | 分析者の見立てが、次の回も分析者の言葉のまま残る | Want | 解決 | 高（Claude の推測、人間が推奨を採った） | 課題2 |
| W2 | 誰の読みかを、読み手が見分けられる | Want | 解決 | 中（Claude の推測） | 課題3 |
| W3 | 変える所の広さ | Want | 費用 | 中（Claude の推測） | YAGNI |

- 案a: 型は変えない。見立てを claim に起こし、SKILL.md の決まりだけを変える。
- 案b: 見立てを、id を持つ新しい記録として論点ツリーに持つ。答えの文がそれを引用する。
- 案c: 答えの文に分析者の見立ての印を持たせる。本文は分析者の言葉で、引用はエージェントが推奨する。
- 何もしない。

| Must | 案a | 案b | 案c | 何もしない |
|---|---|---|---|---|
| M1 | 満たす | 満たす | 満たす | 満たす |
| M2 | 満たす | 満たさない恐れがある。見立てを引用先に数えると、見立ての中の数が検査を通る | 満たす | 満たす |

| Want | 案a | 案c |
|---|---|---|
| W1 | 残らない。印が無いので、次の回のエージェントは分析者の見立てと自分の文を区別できず、直す | 残る。印のある文は一字一句そのまま送らせる |
| W2 | 見分けられない | 見分けられる |
| W3 | SKILL.md だけ | モデルに項目を1つ、`tree_io answer` の入力、表示の印。検査と、答えの変化の比べ方は変えない |

- 差がつく基準: W1 と W3。
- 感度: W1 を低く見るなら、案a が最も安い。

| 案 | 起きうる悪い結果 | 抑え方 |
|---|---|---|
| 案a | 分析者の言葉が、次の回に知らないうちに書き換わる | 無い |
| 案b | 見立てと、それを言い直した答えの文が食い違う | 見立てそのものを検査する規則を足す。費用が大きい |
| 案c | 数を含まない言い過ぎが、分析者の見立てとして通る | 印を画面に出す。言ったのが分析者だと読み手に分かる |
| 案c | 新人の分析者が、見立てを言えずに詰まる | 見立ては任意にする。エージェントの下書きから始められる |
| 何もしない | 課題1〜3 が残る | 無い |

## Decision

案c を採る（人間の判断、2026-11-28）。決め手は W1 と W3 である。ADR-0025 の Decision のうち、「答えの文はエージェントが書く」を次のように改訂する。
引用と検査の決まりは変えない。

1. 答えの文は分析者の見立ての印を持てる。印のある文の本文は分析者の言葉である。印の無い文は今までどおりエージェントが書く。
2. 印のある文も journal の出来事を1つ以上引用する。引用はエージェントが推奨し、分析者が確かめる。ツリーの検査を同じ規則で受ける。
3. エージェントは印のある文を言い換えない。後の回の振り返りは一字一句そのまま送る。検査の違反は言い換えずに分析者に聞く。
   変えるのは、分析者が変えると言ったときだけである。
4. テーマの振り返りは主題の答えを書く前に、この回の結果が主題にどう効くかを分析者の言葉で聞く。聞くのは主題についてだけである。
5. 見立ては任意である。分析者はエージェントの下書きから始めることを選べ、そのときは今までどおりエージェントが主題の答えを書く。
6. 論点ツリーの HTML とレポートは印のある文に、分析者の見立てと分かる印を出す。

## Consequences

### Positive

- 分析設計をまたいだ分析者の見立てが、主題の答えに分析者の言葉で残る。
- 論点ツリーの決定の理由と同じ型（分析者の言葉、エージェントが探す根拠、検査は分析者に聞く）なので、新しい仕組みが要らない。
- 新人の分析者は下書きから始めれば今までどおり進める。ADR-0025 の W2 を保つ。

### Negative

- 数を含まない言い過ぎは、分析者の見立てとしても通る。塞がない。印で誰が言ったかを見せるだけである。
- テーマの振り返りで分析者が止まる回数が、見立てを言う1回ぶん増える。下書きから始めても、根拠を確かめる問いは省けないので、回数は同じだけ増える（1回目の返事が一言で済むだけである）。
- 見立てを聞くのは主題だけである。途中の論点で分析者が見立てを言いたいときは、エージェントに文を直させるしかない。
- 分析者の見立てを、エージェントがどの種類（これまでわかっていること・注意すべきこと・まだ決められないこと）に置くかは、
  読み上げて分析者に確かめる。置き間違いは、分析者が気づくのに頼る。

## Alternatives considered

- **テーマの journal を作り、見立てを出来事として積む** — journal の出来事の種類と、それを読む所の全部に波及する。案b と同じく、見立てを引用先に数えることになるので落とした。
- **`conclude` を主題にも書けるようにする** — `conclude` は分析設計を終える出来事で、分析の段階を決める。意味が2つになるので落とした。
