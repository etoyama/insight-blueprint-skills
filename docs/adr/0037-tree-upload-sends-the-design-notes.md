# ADR-0037: `/tree-upload` は、分析ノートを含む論点ツリーの HTML を、1ファイルのまま Artifact に送る

## Status

Accepted

## Context

[Epic 28](../design/epic-28-tree-entry-point.md) は論点ツリーの HTML の中に、分析設計ごとの分析ノートを並べる（[ADR-0036](0036-design-note-is-a-generated-page-per-design.md)）。
`/tree-upload` は、論点ツリーの HTML を Artifact に送る skill である（[Epic 18](../design/epic-18-question-tree.md) の US-6）。
分析ノートを含めて送るかを、2026-11-22 に DesignDoc 初版のセッションで人間と決めた。
人間は最初に「手元の HTML だけを入口にする」と答え、分析ノートの形が決まった後に「全部 Artifact にしてリンクしてはまずいか」と問い直した。

比較の前提にした事実と、確かめた方法は次のとおり。

- `/tree-upload` は、`tree_io render` が書いた1ファイルだけを、書き換えずに送る（`skills/tree-upload/SKILL.md`、Epic 18 の US-6 AC 3）。
- Artifact の中で通る移り方は、同じページの中のアンカーだけである。別の HTML を添えて送っても、スマホのアプリでは開けない（ADR-0036 の Context。人間が確かめた）。
  そのため、分析ノートは論点ツリーの HTML と同じ1ファイルに入っている。
- 分析ノートは図・指標の値・journal のすべての出来事・分析コードを載せる。結論の後は結論・勧め・振り返りの本文も載せる。データ取得のコードと接続情報の値は載せない（ADR-0036）。
  今の論点ツリーの HTML が載せるのは、問い・答え・引用した出来事の本文・分析設計の題と状態までである。
- 外へ送るときは、送るファイルを列挙して KEEP ゲートで承認を待つ。列挙と同じ画面に、送った物が誰に見えるかを書く（[ADR-0016](0016-approval-before-external-send.md)）。
- Artifact のページの上限は 16MB である（Artifact ツールの説明）。見本（分析設計3つ、図3枚）は 126KB だった。
- 製品の成功基準は、論点ツリーの表示を渡された読み手が、現在地と次の一手を説明できることである（[docs/PRD.md](../PRD.md)、引き継ぎの試行）。

## Problem

- 課題1: Artifact で論点ツリーを受け取った人は、今は論点から根拠へたどれない。
- 課題2: 分析ノートを含めて送ると、外へ出る中身が広がる。分析者が、何が出るかを知らずに承認する恐れがある。
- 課題3: 1ファイルにしたので、分析ノートを含まない論点ツリーだけを送ることが、そのままではできない。

扱わない範囲: notebook の `.py`・verdict・Markdown のレポートを Artifact に送ること。論点ツリーの無いテーマの分析ノートを送ること。Artifact を作った後の共有。

## Decision

s1 を採る（人間の判断、2026-11-22）。決め手は W1 と W2。

- `/tree-upload` は、`tree_io render` が書いた論点ツリーの HTML を、分析ノートを含む1ファイルのまま送る。添えるファイルは送らない。モデルは書き換えず、写しも作らない。
- 列挙するのは、今までどおり論点ツリーの HTML のパス1つである。
- 承認の文に、ページに載る中身を書く。中身は論点ツリーに加えて、分析設計ごとの分析ノート（手法、指標の値、図、journal のすべての出来事、分析コード、結論の後は結論と振り返りの本文）である。
  分析ノートを含まない論点ツリーだけを送る手段は無いことも書く。
- ファイルが Artifact の上限（16MB）を超えるときは、承認を聞く前にそう伝え、何も送らない。
- notebook の `.py`・verdict・Markdown のレポート・notebook の HTML は送らない。接続情報の値が外へ出るためである（[ADR-0022](0022-connection-reaches-only-the-notebook.md)）。
- 承認の決まり（ADR-0016）は変えない。承認は1回の実行に限り、覚えない。
- 「アップロード」の定義と [docs/ARCHITECTURE.md](../ARCHITECTURE.md) の KEEP ゲートの一覧は、実装の Story で直す。

## Consequences

### Positive

- Artifact で論点ツリーを受け取った人も、論点から分析ノートへたどり、結果と図とコードを確かめられる。
- 手元と Artifact で同じ1ファイルを読む。`/tree-upload` の手順は承認の文のほかは変わらない。

### Negative

- 外へ出る中身が広がる。機密や個人情報が無いかは、分析者が送る前にページを開いて確かめるしかない（ADR-0016 と同じ限界）。
- 論点ツリーだけを渡したい場面では送れない。この決定の前は送れていた。
- 分析ノートの「手元のファイル」の節のリンクは、Artifact では開けない。
- 分析設計と図の多いテーマでは、ファイルが上限を超えて送れなくなる。そのときに大きさを抑える手段は決めていない。
- 論点ツリーの無いテーマの分析ノートは、Artifact に送る手段が無い。

## Alternatives considered

- **分析ノートを別の HTML として添えて送る** — スマホのアプリでは開けず、デスクトップでは元のページに戻れなかった（ADR-0036 の Context）。初版ではこの形を採ろうとし、見本で確かめて落とした。
- **notebook の `.py` と verdict も Artifact に送る** — データ取得の cell の接続情報の値が外へ出る（ADR-0022）。
