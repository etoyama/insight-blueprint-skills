# FLOW-0009: DesignDoc 初版では、成果物の単位と範囲の判断を先に聞き、中身で迷ったら見本を見比べてから決める

## Status

Accepted

## Context

[docs/WORKFLOW.md](../WORKFLOW.md) §4 の2は、DesignDoc 初版で埋める節と、承認を求める前の2段（全体の整合、見本）を決めている
（[FLOW-0005](0005-designdoc-draft-checks-whole-and-mockup.md)）。初版の判断をどの順で人間に聞くかは決めていない。
見本は、判断がそろった後に作るものとして書いてある。

このテンプレートの派生先の Epic 29（etoyama/insight-blueprint-skills、#177、2026-11-23）で、次のことが起きた。
PM セッションの振り返りで、ボードのログと PM の会話から確かめた。

- DesignDoc の判断で、D2（含意の文章を載せるか）を決めた後に、D3a（export の単位はテーマ）が決まった。
  D3a を受けて、D2 を決め直した。
- 決め直しは含意あり・なしの見本 A/B を見比べて決まった。

全体の整合の段（FLOW-0005）は、そろった判断の矛盾を見つける。D2 の決め直しは、その段より前に、
順番の問題として起きた。

## Problem

- 課題1: 成果物の単位や範囲を決める判断を、中身を決める判断の後に聞くと、中身の判断を決め直すことになる。
  人間は同じ論点に2回答える。
- 課題2: 中身の判断は文と表だけでは案の違いを思い描きにくい。迷ったまま決めると、見本を見た後で決め直すことになる。

扱わない範囲: 初版の後の2段（FLOW-0005 のまま）。Story の実装中の判断の順。

| 案 | 起きうる悪い結果 | 抑え方 |
|---|---|---|
| A | 「単位と範囲の判断」の見分けがつかず、順が守られない | 例を書く（何を単位に作るか、誰に届けるか） |
| A | 判断の途中の見本が増え、初版が遅れる | 迷った判断だけに使う。見本はコミットしない（FLOW-0005） |
| B | PM を通さない初版では、同じ決め直しが起きる | なし |
| 何もしない | D2 と同じ決め直しが繰り返される | 全体の整合の段で拾えるが、人間は2回答える |

## Decision

A を採る。DesignDoc 初版の判断は次の順で人間に聞く。手順の正本は [docs/WORKFLOW.md](../WORKFLOW.md) §4 の2に置く。

- 成果物の単位と範囲を決める判断（何を単位に作るか、誰に届けるか）を、中身を決める判断より先に聞く。
- 中身の判断で迷ったら、決める前に、案ごとの見本を見比べてもらう。FLOW-0005 の見本の段は判断の途中にも使える。

人間が束 C として採った（派生先の Epic 29 の振り返り、2026-11-23）。決め手は W3。

## Consequences

### Positive

- 単位と範囲が決まってから中身を聞くので、中身の判断の決め直しが減る。
- 迷った判断は見本を見て一度で決まる。

### Negative

- 根拠は1件（Epic 29 の D2）だけである。ほかの Epic で順が効くかは確かめていない。
- どの判断が「単位と範囲」に当たるかの見極めは、初版を書く AI に任せる。

## Alternatives considered

- **FLOW-0005 を改める** — FLOW-0005 は初版の後の2段を決めている。判断の順は別の決定なので、1ファイル1決定に従って分ける。
