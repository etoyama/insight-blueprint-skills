# FLOW-0020: DesignDoc 初版で、見本へのコメントを反映した後に、全体の整合をもう一度回す

## Status

Accepted

## Context

[FLOW-0005](0005-designdoc-draft-checks-whole-and-mockup.md) は、DesignDoc 初版の承認の前に、全体の整合と見本の2段を置いた。
順は、全体の整合が先で、見本が後である。見本へのコメントを反映した後に、整合を確かめ直す決まりは無い。

このテンプレートの派生先の Epic 34（etoyama/insight-blueprint-skills、[#249](https://github.com/etoyama/insight-blueprint-skills/issues/249)、2026-11-26）で、
次のことが起きた。振り返り（#249 の[コメント](https://github.com/etoyama/insight-blueprint-skills/issues/249#issuecomment-7185439265)の事実の表と学び7）で確かめた。

- 初版の見本に、人間のコメントが7件付いた。子はコメントを反映し、人間が初版を承認した。
- 承認の後、用語集の対応表が本体と食い違っているのが見つかった。同じ日に ADR を直した。
- 見本へのコメントを反映した後、全体の整合は回していなかった。

## Problem

- 課題1: 見本へのコメントは、言葉や形を変える。変えた所を写している所（用語の表、AC、Scope、図）が古いまま残ると、食い違った DesignDoc が承認される。
- 課題2: 食い違いが承認の後に見つかると、直しが ADR や Story のブリーフに及ぶ。
- 課題3: 整合を回す回数が増えると、初版の手間が増える。

扱わない範囲: Story の実装が始まった後の DesignDoc の整合（Story の完了の条件とゲートが扱う）。

## Decision Analysis

| # | 基準 | 区分 | 分類 | 重み（決めた人） | 出典 |
|---|---|---|---|---|---|
| M1 | 承認を求める時点の DesignDoc が、最後に変えた後に、全体の整合を通っている | Must | - | - | 課題1 |
| W1 | 判断どうしの矛盾が、見本を作る前に見つかる | Want | 解決 | 高（Claude の推測。FLOW-0005 の狙い） | FLOW-0005 |
| W2 | 初版の手間が増えない | Want | 費用 | 中（Claude の推測） | 課題3 |

| Must | A. 見本へのコメントを反映したら、整合をもう一度回す | B. 順を入れ替え、整合を見本の後の1回だけにする | 何もしない |
|---|---|---|---|
| M1 | 満たす | 満たす | 満たさない（反映の後は誰も見ない） |

| Want | A | B |
|---|---|---|
| W1 | 1回目の整合が見本の前に残る | 矛盾した判断のまま見本を作りうる。見本の作り直しになる |
| W2 | 反映で文書を変えたときだけ、もう1回回す。2回目は、変えた所と、それを写している所に絞れる | 回すのは1回 |

- 差がつく基準: W1 と W2。
- 感度: W1 を低くすると B が勝つ。W1 は Claude の推測だが、FLOW-0005 が整合を先に置いた理由と同じである。

| 案 | 起きうる悪い結果 | 抑え方 |
|---|---|---|
| A | 2回目が形だけになる（「問題なし」と書くだけ） | 反映で変えた所を挙げ、それぞれを写している所を挙げて、1つずつ見る |
| A | 2回目に直した所が、また別の所とずれる | 2回目で文書を変えたら、変えた所だけをもう一度見る |
| B | 矛盾した判断で見本を作り、作り直す | 抑えられない |

## Decision

A を採る。手順の正本は WORKFLOW §4 の2 に置き、FLOW-0005 の2段の後に足す。

- 見本へのコメントを反映して DesignDoc や ADR を変えたら、承認を求める前に、全体の整合をもう一度回す。
- 2回目は、反映で変えた所を挙げ、それを写している所（用語の表、AC、Scope、図、関係する ADR）を1つずつ見る。
- 見本へのコメントが無い、または反映で文書を変えなかったときは、回さない。

人間が束 B として採った（派生先の Epic 34 の振り返り、2026-11-26）。決め手は M1 と W1。

## Consequences

### Positive

- 見本の反映で生まれた食い違いが、承認の前に見つかる。
- 2回目は見る所が絞られるので、1回目より軽い。

### Negative

- 初版の承認までの手間が増える。
- 写している所を挙げきれるかは AI に任せる。挙げ漏れた所の食い違いは残る。
- 2回目を回したかどうかを機械的に検査する仕組みは入れていない。
- 根拠は1件（Epic 34）だけである。

## Alternatives considered

- **用語の表などの写しを、機械的に本体と突き合わせる** — 何を写しとみなすかがリポジトリごとに違う。テンプレートには置かず、要るリポジトリが構造テストで足す。
