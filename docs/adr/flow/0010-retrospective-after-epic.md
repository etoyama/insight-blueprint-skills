# FLOW-0010: Epic のリリースの後に、軽量な定型の振り返りを回す

## Status

Accepted

## Context

[docs/WORKFLOW.md](../WORKFLOW.md) §4 のライフサイクルは、Epic PR のマージで終わる。
フローそのものを直す場は決めていない。

このテンプレートの派生先（etoyama/insight-blueprint-skills）は、Epic 28 と Epic 29 の後に、PM セッションで振り返りを回した。

- Epic 28（2026-11-23）の振り返りから、FLOW-0006〜0008 が上流のこの repo に入った（[#5](https://github.com/etoyama/repo-template/pull/5)、[#6](https://github.com/etoyama/repo-template/pull/6)）。
- Epic 29（#177、2026-11-23）の振り返りは、事実 → 学び → 反映の束 → 人間が選ぶ、の順で1回で回せた。
  人間は A・B・C の3つの束を上流に入れると選び、振り返り自体も定型にしてほしいと頼んだ。
  下敷きにするよう頼まれたのは、Derby と Larsen の5段（場を作る、データを集める、洞察を出す、何をするか決める、閉じる）と、
  人を責めない書き方（Kerth の Prime Directive、SRE の blameless postmortem）である。
- 2回とも、振り返りの手順はその場の PM の判断で決まった。集める物も出す形も正本には無かった。
- 振り返りで集めた物は、ボードのログ（Artifact の db）、`git log`、issue のコメント、共有ノートだった。
  このうちボードと共有ノートは、PM セッション（[FLOW-0006](0006-pm-session-and-board.md)）の道具に依存する。

## Problem

- 課題1: 振り返りを回すかどうか、何を出すかがセッションの判断に任されている。回さない Epic では、フローの詰まりが次の Epic に持ち越される。
- 課題2: 出す形が決まっていないと、学びが事実に結び付かず、反映の置き場（テンプレート、このリポジトリ、メモリ）も選べない。
- 課題3: 反映したことが効いたかを確かめる場が無い。

扱わない範囲: 振り返りで見つけた個々の改善の中身。KPT などほかの型との比較の詳細。

| 何もしない | 振り返りが回るかどうかが運になる。反映の効き目も確かめない | なし |

## Decision

A を採る。Epic のリリースまで終えたら、振り返りを1回回す。人間が頼んだときも回す。

- 定義（いつ、何を出すか、どこに残すか）の正本は [docs/WORKFLOW.md](../WORKFLOW.md) §4 の6に置く。
- PM セッションでの回し方（集める物、出し方、反映の分け方）は [.claude/skills/pm-session/SKILL.md](../../.claude/skills/pm-session/SKILL.md) §9 に置く。

出す物は次の4つで、1回で出す。

1. 事実: 時刻つきの流れ、人間が決めたことの一覧、起きたこと（詰まり、やり直し、うまくいったこと）。人を責めず、手順と仕組みの言葉で書く。推測は推測と書く。
2. 学び: 1件ごとに根拠の事実を指す。続けること（うまくいったこと）も入れる。
3. 反映の案: 束ごとに、置き場と中身を表にする。
4. 前回の振り返りで反映したことが効いたか（1件ずつ1行）。

反映する束は人間が選ぶ。フローの定義を変える束は ADR を伴う。振り返りの全文は Epic issue のコメントに残し、ファイルとしてはコミットしない。

人間が定型にすると頼んだ（派生先の Epic 29 の振り返り、2026-11-23）。決め手は M1。

## Consequences

### Positive

- Epic ごとに、フローの詰まりが事実つきで出て、反映の置き場まで決まる。
- 前回の反映が効いたかを、次の振り返りで確かめられる。

### Negative

- Epic ごとに、振り返りの1往復が増える。
- 振り返りの全文はコメントに残るだけで、横断して検索する仕組みは無い。
- 前回の振り返りを見つけるには、前の Epic issue をたどる必要がある。

## Alternatives considered

- **KPT（Keep / Problem / Try）の型にする** — 事実を集める段が無く、学びが事実に結び付きにくい。5段の型は「データを集める」を独立した段に持つ。
- **振り返りをファイルとしてコミットする** — 反映した結果は ADR とスキルに残る。全文まで repo に置くと、正本でない文書が増える。
